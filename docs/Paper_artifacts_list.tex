\section*{Protocol parameters (naming, fixed defaults, and the two variants)}
The deployed evaluation fixes three protocol parameters; \emph{two} of these are now
swept as separate paper parts:
\begin{itemize}[leftmargin=1.5em,itemsep=1pt]
  \item \textbf{K --- warm-up fraction} (default $0.40$ in Setting~A; \textbf{$0.20$ in
  Setting~B, paired with $G\!=\!50$}). Sweep: \{.05,.1,.2,.3,.4,.5\}. Discussion~D2 /
  Appendix~H.
  \item \textbf{M --- block size} (refit/predict granularity; default \textbf{200}).
  Sweep: \{10,25,50,100,200\}. \textbf{This is the renamed ``block'' part} (was
  conflated with the gap). Discussion~D3-block / Appendix~H.
  \item \textbf{G --- verification-latency gap} (default \textbf{0}; labels revealed at
  the block boundary). \textbf{New part: also generate every performance/evaluation
  artifact in Setting~B $\{G\!=\!50,\ K\!=\!0.20\}$} and keep both settings (choose per
  section later). Sweep (optional): \{0,10,25,50,100\}. Discussion~D3-gap.
\end{itemize}
\textbf{Note on W (trajectory window, 150 accurate / 800 smoothed):} W affects only
stream-plot smoothing, \emph{not} any end-of-stream metric/table number; regenerating
at any W is always \Ctwo\ from cached raw scores.

\textbf{Two PAIRED evaluation settings to produce for every performance/evaluation
artifact (tables + stream figures):}
\begin{itemize}[leftmargin=1.5em,itemsep=1pt]
  \item \textbf{Setting~A (current):} $\{G\!=\!0,\ K\!=\!0.40\}$ --- suffix \code{\_g0}
  (equivalently \code{\_g0k40}). All existing results are this setting.
  \item \textbf{Setting~B (new):} $\{G\!=\!50,\ K\!=\!0.20\}$ --- suffix \code{\_g50}
  (equivalently \code{\_g50k20}). \emph{The gap and the warm-up change together}: whenever
  $G\!=\!50$ is used, $K$ is $0.20$, not $0.40$. These are two \emph{paired} settings,
  \textbf{not} a $G\times K$ grid.
\end{itemize}
Raw scores and result pickles for both settings must be saved for future reuse.
Applying a gap $G$ and a different warm-up $K$ both operate on cached per-commit scores
(shift which labels are revealed / where scoring starts), so Setting~B is \Ctwo\
\emph{where \code{raw\_method\_scores}/\code{raw\_fusion\_scores} exist}; otherwise
\Cthree\ (needs the resident re-run first). Because the whole Setting~B pass is
requested as part of the \Cthree\ stage, it is scheduled there, but on projects with
cached raw scores it will in practice run cache-only. \emph{(The $K$-sweep of D2/App~H
still spans \{.05,.1,.2,.3,.4,.5\} independently; the $K\!=\!0.20$ here is only the
default paired with $G\!=\!50$.)}
